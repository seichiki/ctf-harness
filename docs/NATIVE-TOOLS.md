# Project-local native tools / クローン内の外部ツール

## Install on Ubuntu 26.04 x86-64 WSL

```sh
uv sync --locked
./scripts/setup-native-tools.sh
./ctf-start tools --missing-only --json
uv run --offline --locked --no-sync python scripts/native_smoke.py
```

The installer downloads signed Ubuntu packages through the system's configured
official apt repository and extracts them into ignored `.local/tools/ubuntu-root/`.
It does not run `sudo`, change apt's system database, grant capture privileges,
configure a proxy, or alter the user's shell PATH. The launcher adds
`.local/tools/bin` to **Codex role shells** through scoped CLI configuration; it
does not inject tool variables into the parent Codex API environment. Binwalk 3.1.0
is built from the [canonical crates.io package](https://crates.io/crates/binwalk/3.1.0)
with `cargo install --locked` and the [official Rustup](https://rust-lang.org/tools/install/)
toolchain 1.99.1, both under `.local/tools/`. The setup script installs needed Ubuntu
build metadata locally. This is a supported-host recipe; Ubuntu repository package
versions can change. See `docs/TOOL-INVENTORY.md` for the exact versions observed here.
The [Ubuntu package manifest](NATIVE-APT-MANIFEST.md) records exact downloaded versions
and SHA-256 values, generated by `uv run --offline --locked --no-sync python
scripts/generate_native_manifest.py` after setup.

| Tool | What existing tools cover | Distinct gap filled and verified scope |
| --- | --- | --- |
| GDB 17.1 | Ghidra/REA and binutils provide static disassembly and decompilation. | Live breakpoints and register inspection on a self-built local ELF passed. Codex child ptrace permission remains untested. |
| socat 1.8.1.1 | pwntools can script individual connections. | Transparent bidirectional device/stream relay; a local PTY-to-PTY relay passed. No external relay was tested. |
| ExifTool 13.50 | ExifRead reads EXIF; Pillow reads selected image metadata. | Broader format-specific metadata inspection and editing. A local PNG file-type read passed; editing was not smoke-tested. |
| TShark 4.6.4 | Scapy parses and crafts many packet structures. | Wireshark dissectors and offline protocol field extraction. Local PCAP IPv4/UDP decoding passed. No live capture or group/capability change was made. An optional Falco plugin currently warns about missing `libsinsp.so.0`; the tested decoding still works. |
| Binwalk 3.1.0 | `file` and `strings` can spot some bytes by hand. | Offset-aware embedded signatures and extraction. A local embedded ZIP was detected and extracted. This required local 7-Zip 26.00; other formats may need additional extractors. The deprecated PyPI `binwalk` package was not used. |
| 7-Zip 26.00, unzip 6.00 | Python's `zipfile` can handle simple ZIPs in scripts. | Standalone extractors for tool workflows; 7-Zip was verified through Binwalk's ZIP extraction. |

`./ctf-start tools` is read-only. Its `available` result means the executable launched
and reported a version; it does not prove every function or sandbox permission.
Run the offline smoke command above on a new clone. The fixture uses a self-built ELF,
a generated PNG, a generated PCAP, an embedded ZIP and local PTYs; it makes no live
target requests. Unknown challenge binaries and archives remain untrusted input and
should be handled within the existing role sandbox and authorized scope.

## 日本語

Ubuntu 26.04 x86-64 の WSL では上の `./scripts/setup-native-tools.sh` で、GDB、socat、
ExifTool、TShark、Binwalk 3、7-Zip、unzip をクローン内の `.local/tools/` に導入します。
sudo、システム全体の apt 設定、ユーザーの PATH、パケット取得権限は変更しません。
ハーネスの役のシェルからはクローン内のコマンドを使えます。`tools` は起動と版を
確認するだけなので、上のオフライン試料テストも実行してください。

既存の Ghidra は静的解析用であり、GDB の実行時ブレークポイントとは異なります。
Scapy と TShark、ExifRead/Pillow と ExifTool、`file`/`strings` と Binwalk も
一部は重なりますが、表の固有機能があるため追加しました。Binwalk の ZIP 抽出には
7-Zip が実際に必要でした。TShark はローカル PCAP を読めましたが、任意の Falco
プラグイン警告が残ります。実問題やライブ通信での使用は今回検証していません。
